# ICS 499 – Capstone Project Repository

## Purpose of This Repository

This repository serves as your **team’s shared workspace** for collaborative capstone work.

You will use GitHub to:
- collaborate on code and artifacts,
- track changes and iterations,
- coordinate work as a team,
- and maintain a professional project record.

> **Important:**  
> While GitHub is your collaboration and development environment, **all formal grading submissions must be submitted through D2L Brightspace** as directed in the course.  
> GitHub is not the grading submission system.

---

## Professional Expectations

This repository is treated as a **professional workspace**, similar to what you would use in an internship or early-career role.

You are expected to:
- contribute regularly and responsibly,
- communicate with your teammates,
- use version control appropriately,
- and maintain a clear, organized structure.

Contribution history may be reviewed to understand collaboration patterns, but assessment focuses on **outcomes, clarity, and demonstrated understanding**, not raw activity metrics (e.g., number of commits).

---

## Repository Structure (Suggested)

You may adapt this structure as needed, but changes should be intentional and agreed upon by the team.

---

## README Expectations (Your Responsibility)

You are expected to **update this README** over time to include:
- a brief project description,
- the problem you are solving,
- your intended users or stakeholders,
- and the current status of the project.

Think of this as a document a new team member or manager could read to understand your work.

---

## Branching and Workflow

Keep workflow simple and professional:

- `main` branch should remain stable
- use branches for feature or design work
- pull requests are encouraged for:
  - significant changes,
  - design decisions,
  - or team review points

You are not required to follow a heavy GitFlow process. Use what supports clarity and collaboration.

---

## Use of AI Tools

AI tools **may be used** to support your work (e.g., brainstorming, refining text, exploring approaches), unless explicitly directed otherwise.

However:
- repository content must reflect your team’s understanding,
- decisions must be explainable by the team,
- and work should be in your own voice.

> Use AI to **amplify your thinking**, not replace it.

Content that appears to be largely unexamined AI output may be considered ineffective in professional terms.

---

## Assessment Reminder

- GitHub is your **working space**
- D2L Brightspace is the **official submission channel**
- Grades reflect how effectively you apply learning to produce results that create value

If you have questions about expectations, tooling, or need accommodations, contact the instructor early.

---

## Final Note

Treat this repository as something you would be comfortable showing:
- a hiring manager,
- a technical lead,
- or a future teammate.

That mindset will serve you well beyond this course.
